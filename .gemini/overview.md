# **オーケストラ団体向けWebアプリのアーキテクチャと機能群**

ご要望のあった機能要件・技術要件に基づき、Next.js, Clerk, Convex を活用したモバイルネイティブなWebアプリケーションのアーキテクチャ設計と、それに伴う主要な機能群を以下に提案します。

## **1. アーキテクチャ設計**

アプリケーションかの全体像は、フロントエンド、認証、バックエンドが疎結合に連携する構成となります。

### **全体像**

* **フロントエンド (Frontend):** **Next.js + TypeScript** でUIとユーザーインタラクションを構築します。UIコンポーネントには **shadcn/ui** を採用し、高いカスタマイズ性と保守性を実現します。  
* **認証 (Authentication):** **Clerk** がユーザー登録、ログイン、セッション管理、ソーシャルログイン（Google認証）の全てを担います。  
* **バックエンド (Backend):** **Convex** がデータベース、サーバーレス関数、リアルタイム通信基盤を提供します。  
* **デプロイ/ホスティング (Deployment):** **CloudflarePages**を利用し、CI/CDパイプラインを自動化。Gitリポジトリへのプッシュをトリガーに、ビルドからデプロイまでをシームレスに実行します。

### **技術要素ごとの役割**

#### **A. フロントエンド (Next.js + TypeScript)**

* **App Router:** app ディレクトリベースのルーティングを採用し、レイアウトやページの管理をコンポーネント単位で直感的に行います。  
* **UI (shadcn/ui):**  
  * **コンポーザブルな設計:** 必要なコンポーネントのコードを直接プロジェクト内に取り込むスタイルにより、デザインシステムの完全なコントロールと自由なカスタマイズが可能です。  
  * **Tailwind CSSベース:** スタイリングはTailwind CSSのユーティリティクラスをベースにしており、一貫性のあるデザインを効率的に構築できます。  
* **状態管理:** Convexが提供するReactフック (useQuery, useMutation) をクライアントコンポーネント内で使用し、バックエンドとのデータ同期をリアルタイムかつ効率的に行います。  
* **テーマ機能の実装:**  
  * グローバルCSSでデフォルトのテーマカラー（薄いグレー）を定義します。  
  * ユーザーが団体を選択した際、その団体の themeColor をConvexから取得します。  
  * 取得したカラーコードをCSS変数（例: --primary）にセットすることで、アプリケーション全体のアクセントカラーを動的に変更します。shadcn/ui はCSS変数をベースに設計されているため、この方法と非常に相性が良いです。  
* **フィルター機能の実装:**  
  * アプリのヘッダーやサイドバーに、演奏会を選択するためのドロップダウン（shadcn/uiの Select コンポーネントなど）を設置します。  
  * ユーザーが演奏会を選択すると、そのID (concertId) がURLのクエリパラメータやグローバルな状態管理（React Contextなど）で保持されます。  
  * この concertId をConvexのクエリに渡すことで、表示される日程やアセットをその演奏会に関連するものだけに絞り込みます。

#### **B. 認証 (Clerk)**

* **認証機能:** ID/PW認証、Google認証、パスワードリセットなどの機能を、Clerkが提供するコンポーネントを組み込むだけで実現します。  
* **セッション管理:** ログインしたユーザーのセッションはClerkが管理し、セキュアなJWT（JSON Web Token）を発行します。  
* **Convexとの連携:** フロントエンドは、Clerkから取得したJWTをConvexへのリクエストに含めます。Convex側では、このJWTを検証することで、**「誰が」**リクエストを送ってきたのかを安全に特定できます。

#### **C. バックエンド (Convex)**

* **データベース:** スキーマ定義が可能なドキュメントベースのデータベース。リアルタイムでのデータ更新と同期に非常に優れています。  
* **Query/Mutation Functions:**  
  * **Query:** データの読み取り用関数。**演奏会ID (concertId) を引数として受け取り、データをフィルタリングするロジック**を追加します。  
  * **Mutation:** データの書き込み・更新・削除用関数。  
* **権限管理:** すべてのQuery/Mutation関数内で、Clerkから渡されたユーザーID (ctx.auth) を元に、**「そのユーザーがその操作を実行する権限を持つか」**をチェックするロジックを実装します。

## **2. データモデル設計 (Convex)**

テーマ機能とフィルター機能の要件を反映した、新しいデータモデル設計案です。

| テーブル名      | 説明               | 主なフィールド                                                        |
| :-------------- | :----------------- | :-------------------------------------------------------------------- |
| users           | ユーザー情報       | clerkId, name, email, imageUrl                                        |
| organizations   | 団体情報           | name, description, **themeColor** (HEX形式の文字列, e.g., "#BDBDBD") |
| memberships     | 所属情報           | userId, organizationId, role                                          |
| **concerts**    | 演奏会プロジェクト | organizationId, name (e.g., "第50回定期演奏会"), date                 |
| events          | 練習等の日程       | organizationId, **concertId**, title, startAt, endAt                  |
| attendances     | 出欠情報           | eventId, userId, status                                               |
| assets          | 楽譜や録音データ   | organizationId, **concertId**, name, type, fileUrl                    |
| seatingCharts   | 席次情報           | organizationId, **concertId**, chartData                              |
| instrumentParts | パート情報         | organizationId, name                                                  |

**ポイント:**

* organizations に themeColor を追加。未設定の場合はフロント側でデフォルト色を適用します。  
* concerts テーブルを新設し、「演奏会」という大きな活動単位を管理します。  
* events や assets など、多くのデータが concertId に紐づくことで、演奏会ごとのデータ分離とフィルタリングが容易になります。

## **3. 主要機能群**

上記のアーキテクチャとデータモデルを基に実現する機能の一覧です。

### **1. ユーザー認証・管理機能**

* サインアップ、ログイン/ログアウト、プロフィール編集

### **2. 団体管理機能**

* 団体作成・編集  
* **テーマカラー設定:** 団体のテーマカラーをカラーピッカーなどで設定する機能 (管理者)  
* メンバー招待、権限管理、団体切り替え

### **3. 演奏会・日程・出欠管理機能**

* **演奏会プロジェクト作成:** 新しい演奏会を登録する機能 (管理者)  
* **データフィルター:** **ヘッダー等に配置されたドロップダウンで、表示するデータを演奏会ごとに切り替える**  
* イベント作成・編集（どの演奏会に紐づくかを選択）  
* カレンダー表示、出欠提出、出欠状況一覧

### **4. メンバー管理機能**

* メンバー一覧、属性管理  
* 席次管理（演奏会ごとに作成）

### **5. アセット管理機能**

* ファイルアップロード（どの演奏会に紐づくかを選択）  
* ファイル閲覧・ダウンロード

## **4. 開発の進め方（提案）**

1. **フェーズ1: 基盤構築**  
   * Next.js + Convex + Clerk のプロジェクトセットアップ  
   * Clerkによる認証機能の実装とCloudflarePagesへのデプロイ  
   * shadcn/uiの導入と**テーマ機能（CSS変数）の基本設定**  
2. **フェーズ2: コア機能開発**  
   * **concerts テーブルを含むデータモデルの構築**  
   * **演奏会フィルターのUI**とロジックの実装  
   * 日程・出欠管理機能の実装  
3. **フェーズ3: 拡張機能開発**  
   * メンバー管理（席次管理）機能の実装  
   * アセット管理機能の実装  
4. **フェーズ4: 仕上げ**  
   * レスポンシブデザインの最終調整と本番デプロイ
